# Conformance matrix

**What has actually been confirmed about the UniFi camera↔controller relationship,
against what device, at what confidence, and which flock tool exercises each side.**

This is a synthesis, not a source. Every row points back to a document that states
the finding in full; where a row and its source ever disagree, the source wins.
The prose write-ups explain *why*; this table exists so you can see *coverage* — what
is nailed down, what is only inferred, and what is still untested — at a glance.

**Device of record:** UVC G5 PTZ, firmware 5.3.95 / middleware v4.70.91, observed
against real UniFi Protect 7.1.77 on `unifi-unvr-emu`. A second reading of the
ONVIF/RTSP re-serve side was taken against real **Home Assistant** (2026.x) and
its ONVIF stack (`python-onvif-zeep`, `python-ws-discovery`).

## How to read it

**Confidence** uses the tags from the [README](README.md):

| Tag | Meaning |
|---|---|
| `[MEASURED]` | Observed on real hardware, or on the wire |
| `[MEASURED-LOG]` | Read from the controller's own plaintext log |
| `[FIRMWARE]` | Read from binaries or strings |
| `[INFERRED]` | Reasoned from the above |
| `[UNVERIFIED]` | In the vocabulary, never exercised |

**Exercised by** names the flock tool that runs this path against real hardware, so
a claim is not only *observed* but *reproduced from scratch*:

| Mark | Meaning |
|---|---|
| **finch** | The synthetic **camera**. Proves the finding is enough to be *adopted by real Protect* and behave as this side. |
| **cuckoo** | The fake **controller**. Proves the finding is enough to *adopt a real camera* and drive this side. |
| **both** | Runs in finch **and** cuckoo — the two meet in the middle with no Ubiquiti hardware in the loop. |
| — | Documented but not yet built into either tool. |

A finding marked `[MEASURED]` **and** carrying a tool is the strongest kind here:
seen on the wire, then regenerated by our own code and accepted by the real peer.

## Transport & discovery

| Behaviour | Confidence | Evidence | Exercised by |

## Adoption handshake

| Behaviour | Confidence | Evidence | Exercised by |
|---|---|---|---|
| **timeSync ping-pong** — camera pings repeatedly, each referencing the controller's last, until its clock converges; only then `hello` | `[MEASURED]` | 263-envelope plaintext capture; observations §9 | both |
| Controller must answer **every** timeSync (reply flag is not a reason to skip) and must **not** speak first | `[MEASURED]` | removing the answer, or speaking first, stalls adoption | cuckoo |
| Camera does **not** apply time from the reply (its clock is the reference) | `[MEASURED]` | measured negative; `protocol-reference.md` | both |
| `hello` carries `adoptionCode:""`; reply carries null `controllerUuid` + `overrideUuid:true` | `[MEASURED]` | plaintext capture | both |
| Settings suite is **ack-gated** — message N+1 released only when N is acked | `[MEASURED]` | observations §9; cuckoo releases one at a time | cuckoo |

## Media (the push)

| Behaviour | Confidence | Evidence | Exercised by |
|---|---|---|---|
| Video is pushed over plain **TCP `:7550`**, `extendedFlv` — **20 bytes between tags**, not FLV's 4 | `[MEASURED]` | `pyunifiwire/flv.py`; walks the real stream | both |
| Camera advertises **`videoCodecs: [h264, h265, mjpg]`** | `[MEASURED]` | adoption featureFlags | both |
| **Real controller requests `type: "h265"`** per track | `[MEASURED]` | plaintext `ChangeVideoSettings`; cuckoo mirrors it | cuckoo |
| Camera can be asked for **`type: "h264"`** instead, and encodes it natively | `[MEASURED-LOG]` | old-cuckoo `adoption.py` set `h264` and the camera streamed it | — |
| HEVC lives under **FLV codec id 8** (no stock demuxer maps it) | `[MEASURED]` | `ffprobe` on the raw stream fails; our deframer succeeds | both |
| HEVC sequence header is **not a standard `hvcC`** — parameter sets length-prefixed, config signalled by FLV **frame type 6** (packet-type byte is 1 even on config) | `[MEASURED]` | `pyunifiwire/hevc.py`; a full frame decodes 2688×1512 | both |
| **H.264 signals config the opposite way** — standard `avcC`, frame **type 1** with `AVCPacketType` **0**, no frame-type-6 tag. A parser must accept either signal | `[MEASURED]` | real camera H.264 track; `avc.parameter_sets` reads the `avcC`, stream decodes | cuckoo |
| Camera runs **three encoder channels at once**, any codec on any channel (incl. **full-res H.264**) | `[MEASURED]` | real G5 PTZ: all three as `h264` (2688×1512 ~8 Mbps, 1280×720, 640×360) at once; also mixed (an `h265` channel beside `h264` ones) | cuckoo |
| Audio is **AAC-LC 16 kHz mono** (SDP must state 16000) | `[MEASURED]` | wrong clock plays at wrong speed | both |
| Re-serve as standard **RTSP** (HEVC RTP, RFC 7798) | `[MEASURED]` | `ffprobe`/`ffplay` read cuckoo's RTSP; a frame decodes clean | cuckoo |
| **H.264 RTP re-serve** (RFC 6184) for clients that require it (e.g. HA ONVIF) | `[MEASURED]` | off the real camera at full res: `ffprobe` reads `h264 / Main / 2688×1512`, 40 frames decode with no errors (also camera-free via `stubcam`) | cuckoo |
| Talkback (AAC out, UDP `:7004`, 22050 Hz) | `[MEASURED]` | observations §12.3; not built | — |
| MJPEG `:7551` | `[UNVERIFIED]` | in vocabulary | — |

## PTZ

| Behaviour | Confidence | Evidence | Exercised by |
|---|---|---|---|
| PTZ rides a **second WebSocket**, subprotocol `ptz1`, opened by the camera after `EnablePtzControl{uri}` | `[MEASURED]` | observations §9; both tools open/accept it | both |
| **No absolute-move verb** — a move is `Preset` `action:config` then `action:go` | `[MEASURED]` | identical `AbsolutePosition` moved the head inconsistently | both |
| Presets carry focus → **four axes** (pan/tilt/zoom/focus) | `[MEASURED]` | preset payload shape | both |
| Motor bounds announced by the camera; moves clamp to them | `[MEASURED]` | adoption payload; cuckoo clamps | both |
| Position both **polled** (`GetCurrentPosition`) and **pushed** (`EventMotorState`) | `[MEASURED]` | observations §9 | both |
| ONVIF `ContinuousMove` → **one relative step** (camera has no continuous mode) | `[INFERRED]` | mapped in cuckoo; HA arrow-key repeats it | cuckoo |
| Wire-level preset **delete** | `[UNVERIFIED]` | none observed; `RemovePreset` forgets locally only | — |

## Open edges

These are the rows above that are **not** yet `[MEASURED]` **and** exercised — the
honest edge of the work:

- **Talkback / MJPEG / wire-level preset delete** — in the vocabulary, never exercised.
- **ONVIF auth** — served open; a real deployment needs it.

Corrections belong here, not in the git history alone: if a row moves from
`[INFERRED]` to `[MEASURED]`, or flips outright, change it here and note it in the
source document's correction log.
